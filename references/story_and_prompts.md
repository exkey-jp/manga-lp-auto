# 参考LPの読み方 → 章立て・コマ一覧・プロンプト（工程①〜③）

サンプル：`examples/sample/panels.json`（コマの書き方）・`config.example.json`（HTMLの組み立て）。設定の `benchmark` に過去の合格LPがあれば、その panels.json・プロンプトを型にする。

## ① 参考LPを読む → `ref_analysis.md`

`ref_capture.py` で取った `ref/s1.jpg…`（番号つき一覧）と `ref/index.json`（画像の間のHTML文字・フォーム部品）を見て、次を書き出す。

1. **型**：画像だけのLPか／画像＋HTMLか。幅（参考は800px画像の縦並び）
2. **登場人物**：何人・誰が説明役か（参考：悩む主婦＋説明役の友人の女性2人）
3. **流れ**：番号ごとに「漫画のコマ／図解／警告帯／CTA／フォーム」を分類し、話の段階（つかみ→悩み→原因→解決策→比較→費用→安心→CTA）に分ける
4. **CTAの位置と回数**、フォームの形（何問・何を聞くか）
5. **使えない表現**：参考LPにある NG（例：初期費用0円・電気代0円・60%割引・先着順）を `expression_rules.md` で判定し、「このLPでは使わない」表にする
6. 真似る点（構図・吹き出しの形・図解の見せ方）を5行

参考LPの画像・文言・人物はコピーしない。**構成と見せ方だけ**参考にする。

## ② 章立て・コマ一覧・プロンプト

### 一次情報の優先順位
1. クライアントのLP戦略シート・ワイヤー（LP戦略シート・ワイヤーフレーム等）… **章立てはワイヤーの順に合わせる**
2. クライアントの公式サイト・既存LP … 使ってよい数字・サービス名・対応エリア・CTA
3. 公的な数字（補助金上限・相談件数・料金単価）… 出典URLを控え、注記にする
4. 分からない数字は作らない → `{{要確認：〜}}` にして `要確認リスト.md` へ

### 話の型（太陽光＋蓄電池の漫画LPで合格した6章。商材に合わせて言い換える）
| 章 | 役割 | コマの例 |
|---|---|---|
| FV | 誰向け・何がわかる・いくら | 縦長1枚（M00）。数字は大きく、対象者を帯で |
| 1 つかむ | 自分ごと化のショック → 不安（訪問販売等） | 2〜3コマ |
| 2 なぜいま？ | 悩みの整理 → 説明役登場 → 原因の図解 → 放置した場合の金額 | 漫画2＋図解2 |
| 3 どうすれば？ | 解決の仕組み（図解）→ ケース別 → **シミュレーター入口（S01）** | 漫画＋図解、直後にHTMLのシミュレーター |
| 4 費用・元は取れる？ | 「高いんでしょ」→ 補助金 → 回収年数 → 締切の事実 | 漫画1＋図解3 |
| 5 どこに頼む？ | 悪質業者への注意 → チェックリスト → サービスとの出会い → 約束3つ | 漫画＋図解 |
| 6 行動 | 手軽さ → 診断書の説明 → 導入後 → 締めのひと言 → 3ステップ → 最終CTA | 漫画4＋図解1＋CTA背景 |

コマ数は**25〜32枚**が目安（合格例は30枚＝M00〜M27＋S01・S02）。

### 画像にするもの／HTMLにするもの
- **画像（ChatGPT）**：漫画のコマ、数字の少ない図解、警告帯、透過の人物イラスト、CTA背景
- **HTML**：注記（※）、表、比較、実例カード、タブ、チェックリスト、FAQ、ギフト・特典、ボタン、シミュレーター、フォーム、会社情報
  - 理由：ChatGPTは文字化け・数字違いが起きる。数字や条件はあとで変わる
- 図解の中の数字は**4つ以内**。それ以上はHTMLの表にする

### ファイル名とサイズ
`M00_fv`, `M01_shock` … のように **番号＋ローマ字の短い名前**。シミュレーター関係は `S01`, `S02`。設定シートは `P0_chara`。

| 種類 | 指定 | 用途 |
|---|---|---|
| 横長 | 1536×1024 | 漫画のコマの大半 |
| 縦長 | 1024×1536 | FV・情報量の多い図解 |
| 正方形 | 1024×1024 | 透過の人物イラスト |

### 送る文の書き方（各コマ）
```
添付のキャラクター{「名前」}で漫画の1コマ。横長1536×1024。
{場所・時間}。{誰が・どこで・何をしている。表情}。{背景の色・効果線}
{人物名}のセリフ：「15文字以内」
擬音：「〇〇」
```
- 人物は**名前で呼び、服や髪の特徴を書かない**（設定シートに任せる）。ただし、ずれやすい人物（説明役の友人・スタッフ）は1行足す：「なおこはキャラクター設定シートどおり、あごの長さのショートボブ・小さな丸いピアスで」
- **書類・スマホ・モニターの中は「文字なし、線と四角だけ」と必ず書く**
- グラフは**目盛りを付けさせない**（棒と数字のずれを防ぐ）。比率を「約4分の1の長さ」のように書く
- 矢印は「◯◯から△△へ向かう矢印」と、始点と終点を書く
- フォームの図は「入力欄が2つ（人のアイコンと電話のアイコン）」のように**数と種類**を書く（実際のフォームに合わせる）
- 透過のコマ：「背景は透過（PNG）。吹き出し・文字は入れない。上半身が切れないよう少し引きで」
- CTA背景：「左半分は文字を後から載せるため無地に近いグラデーションにして、何も描かない」

### 共通ルール（最初に1回送る。`rules.txt`）
次の要点で書き、商材名だけ差し替えて使い回す：
- 画風：日本の縦読み広告漫画、フルカラー、セル塗り、黒い主線、明るい色、外枠は黒の細線1本
- 文字：吹き出しは縦書き・15文字以内。**指定した「」の文字だけを一字一句**。看板・書類・画面の中は文字なし。強調語は赤、数字は太く大きく
- 入れてはいけない：実在の会社・メーカー・ロゴ、指定外の数字や約束（0円・割引）、注意書き（※はWeb側で入れる）
- 登場人物：次に送る設定シートの見た目を全画像で固定

### panels.json（コマ一覧の正本）
```json
{
 "client": "…", "ref_url": "…", "chara_sheet": "P0_chara.png", "max_fix": 3,
 "characters": {"みか": "42歳の主婦。黒髪を低い位置で1つ結び…", "…": "…"},
 "panels": [
  {"id": "M01", "file": "M01_shock", "chapter": "第1章 つかむ", "size": "1536x1024",
   "transparent": false, "characters": ["みか","けんじ"],
   "texts": ["ガーン","電気代 3万円超えてる…!?","先月より上がってない？"],
   "checks": ["スマホ画面に文字を入れない"],
   "html_after": ["※注記…（画像の下にHTMLで入れるもの）"],
   "prompt": "添付のキャラクターで漫画の1コマ。…",
   "status": "todo"}
 ]
}
```
- `texts` は点検で一字一句照合する文字（プロンプトの「」の中身）
- `checks` はそのコマ固有の点検（矢印の向き・棒の比率・入力欄の数・左半分は無地 等）
- `display_ratio`（任意）：LPで幅いっぱいでなく小さく置く画像（チェックリスト横の透過イラスト等）は 0.3 のように書くと、phone.png がその大きさになる

### 人の確認ゲート1（②の終わり）
`プロンプト集.md`（panels.json を読みやすく出したもの：章ごとの流れ・各コマの絵と文字・HTMLで作るもの・シミュレーター仕様・使わない表現の表）と `要確認リスト.md` を `SendUserFile` で送り、**「この流れとコマで進めてよいか」**を聞く。直しが来たら panels.json を直して再提示。

## ③ キャラクター設定シート（人の確認ゲート2）

```
漫画の登場人物{N}人のキャラクター設定シートを作ってください。白背景、横長1536×1024。
各キャラを「正面の全身」と「表情3種（笑顔・驚き・困り顔）」で並べ、名前を小さく添えてください。
1. {名前}（{役}）：{年齢}。{髪型・髪色}。{顔立ち}。{服の色と形}。{クセ・小物}
…
名前の文字：「…」「…」
```
人物を決めるときの約束：
- **並んだときに髪型・髪色・服の色で見分けられる**こと（同じ黒髪の1つ結びを2人に使わない。服の色もかぶらせない：子どもの黄色と友人のからし色が近かった）
- 友人（説明役）とスタッフ（会社の人）は**小物で区別**：スタッフだけ社員証・ベスト、友人はメガネ・社員証なし
- 子どもは年齢と服を固定（「8歳・黄色いTシャツ」）

生成したら `panel_checklist.md` の C（人物）と同じ目で点検し、`P0_chara.png` を送って**人に「この5人で固定してよいか」**を聞く。確定後は**人物が出るすべてのコマで P0 を添付**する。
