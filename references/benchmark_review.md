# 見本（過去の合格LP）と比べる（工程⑥）

目標は「**見本と同じか、それ以上**」。見本は各自の設定 `~/.config/manga-lp-auto/config.json` の `benchmark`（過去に人が○を付けた漫画LP。site・lp.json・panels.json・img）。見本が無い初回は、このファイルの基準だけで判定する。

## 1. 数で比べる

```bash
python3 $S/build_lp.py compare site <benchmark.site>
```
コマ数・縦長の図解の数・章見出し・CTA・注記・HTMLの区切り・シミュレーター・設問数・本文の文字数を表で出す。見本の8割未満は「△」。△は直すか、理由（商材が単純で章が少ない等）を `qa/見本との比較.md` に書く。

## 2. 目で比べる（別AIに採点させる）

見本と今回の両方をスマホ幅（390px）で上から撮り（`qa/screens/` と `qa/bench_screens/`）、Agent で別エージェントに渡す。

```
あなたは広告LPの品質を比べる担当です。作った人とは別の目で見てください。
A（見本・過去に合格したLP）と B（今回）のスマホ画面を上から順に Read で見て、B が A より劣る点を挙げ、B を採点してください。
A：{qa/bench_screens/*.png}　B：{qa/screens/*.png}　B の設定：{lp.json}

■ 比べる観点（各10点、計100点）
1. 構成の流れ：つかみ→悩み→原因→解決→費用→安心→行動、の順に無理なく進む。話が飛ばない
2. コマ数と図解の割合：漫画だけ・図解だけに偏らない（見本の割合に近い）
3. 章ごとのCTA：章の切れ目ごとに行動の入口がある。固定ボタンが最初から出ている
4. シミュレーター→フォーム：途中の1問目を選ぶとフォームへ移り、2問目から続く。答えが引き継がれる
5. スマホでの文字の大きさ：画像のセリフも、HTMLの本文・注記も読める。最終CTAの大きな文字は約28px以上
6. 注記の入れ方：数字・図解・事例・体験談の直後に、出典・計算式・「架空」「当社試算」の注記がある
7. 事例の見せ方：地域が散っている（対応エリアの県を含む）。導入前の金額と削減額・削減率が大きく見える
8. 人物の一貫性：最初から最後まで同じ人物に見える
9. 表現：根拠のない数字・約束・架空の体験談を実例に見せる表現がない
10. 仕上げ：確認用の色付け・「作成例」の表示・未確認の情報・特典の細かい内訳・会社概要（未確認のもの）が出ていない

■ 返す形（JSONのみ）
{"score": 0-100, "pass": true/false, "worse_than_benchmark": [{"point":1-10,"where":"…","detail":"…","fix":"…"}], "better_than_benchmark": ["…"]}
pass は score>=80 かつ worse_than_benchmark に致命的なもの（4・6・9）がないとき true。
```

## 3. 直す

- 80点未満、または 4・6・9 の指摘があれば直して撮り直し、もう一度採点（最大3回）
- 画像が原因（人物・文字の大きさ）なら工程④に戻ってそのコマだけ作り直す
- 結果は `qa/見本との比較.md`（数の表・点数の推移・残った指摘）にまとめ、⑧で人に見せる

## 4. スキルを直したときの回帰テスト

テンプレートやスクリプトを直したら、見本の lp.json から作り直して見本と同じになるかを確かめる。

```bash
python3 $S/build_lp.py build <benchmark.lp_json> --images <見本の画像フォルダ> --out /tmp/bench_rebuild
diff <(sed -n '1,/<script>$/p' <benchmark.site>/index.html) <(sed -n '1,/<script>$/p' /tmp/bench_rebuild/index.html)
python3 $S/build_lp.py compare /tmp/bench_rebuild <benchmark.site>
```
差が出たら、意図した変更かを確かめる。フォームは同じ答えで送信データとサンクスの表示が同じになるかも、ブラウザで確かめる。
